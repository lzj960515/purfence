# issues/（开发过程记录）

本目录用于记录本仓库的需求与开发任务（Markdown Issue）。

> 注意：这与 Purfence 产品里的"Issue"概念同名但不等价。
> 这里的 issues/ 是给仓库开发协作用的；产品里的 Issue 是给最终用户提需求用的。

## 什么时候写 Issue 文档

- 中型/大型功能：开始实现前先写一份 Issue 文档。
- 不确定范围/验收标准：先写 Issue 帮助收敛。
- 多 Agent/多人协作：用 Issue 作为事实源与进度板。

## 推荐模板

新建：`issues/YYYY-MM-DD-<short-title>.md`

包含这些段落即可：

- 背景（为什么做）
- 目标（要达到什么效果）
- 非目标（明确不做什么）
- 范围（包含/不包含）
- 方案（高层设计，必要时给出替代方案与取舍）
- 验收标准（可测试的条目）
- 风险与回滚（可选）
- 进度（checkbox，完成后勾选）

## 与 AGENTS.md 的关系

- `AGENTS.md` 保留“关键约定摘要”。
- 更长的说明放到 `docs/` 与 `issues/`，并在 `AGENTS.md` 的文档索引里链接。
