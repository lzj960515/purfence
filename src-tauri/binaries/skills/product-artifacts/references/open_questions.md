# 开放问题模板与写作指南

## 模板

```markdown
# Open Questions

## Q1: [问题标题]

- **优先级**: P0 / P1 / P2
- **是否阻塞**: 是 / 否
- **为什么重要**: [这个问题为什么必须回答]
- **默认假设**: [如果没有答案，我会按这个假设推进]
- **如何回答**: [建议如何获取答案]

## Q2: [问题标题]

...

---

如果没有需要澄清的问题，写：

None
```

## 写作指南

### 什么问题该放进来

只有满足以下**全部条件**的问题才放入：

1. **影响主流程**：这个问题的答案会显著改变产品方向或核心功能
2. **无法推断**：从上下文中无法合理推断出答案
3. **需要业务判断**：涉及业务策略、成本权衡等需要人决策的事项

### 什么问题不该放

❌ 不要放这些问题：

- 技术实现细节（开发自己能决定）
- UI 细节（设计师自己能决定）
- 常规的边界情况（按最佳实践处理）
- 你可以做出合理假设的问题

### 阻塞 vs 非阻塞

| 类型 | 含义 | 处理方式 |
|-----|------|---------|
| 阻塞 (是) | 不回答就无法继续 | 必须等用户回答 |
| 非阻塞 (否) | 可以先按假设推进 | 记录假设，继续工作 |

### 示例

**好的开放问题**：

```markdown
## Q1: 是否需要支持多币种？

- **优先级**: P0
- **是否阻塞**: 是
- **为什么重要**: 影响数据库设计和金额计算逻辑
- **默认假设**: 仅支持人民币
- **如何回答**: 告诉我需要支持哪些币种
```

**不该放的问题**：

```markdown
## Q?: 按钮用蓝色还是绿色？
→ 这是设计师的决策，不是产品问题

## Q?: 用 MySQL 还是 PostgreSQL？
→ 这是技术决策，不是产品问题

## Q?: 列表每页显示多少条？
→ 按常规做法（10-20条），不需要问
```

### 默认假设的重要性

每个问题都必须有默认假设：

- 如果用户不回答，PM 按假设推进
- 假设应该是合理的、可接受的
- 在 PRD 的"决策与假设列表"中记录这些假设
