# PRD 模板与写作指南

## 模板

```markdown
# PRD

## 标题

[需求标题]

## 用户需求（原文）

[原始需求描述，从 idea.md 引用]

## 目标与非目标

- **目标**：
  - [本次要达成的目标]
- **非目标**：
  - [明确不做的事情]

## 用户与场景

- **目标用户**：[谁会用这个功能]
- **使用场景**：[什么情况下使用]

## 核心用户旅程

1. [用户操作步骤 1]
2. [用户操作步骤 2]
3. [用户操作步骤 3]
...

## 功能清单

### P0（必须有）

- **F1**: [核心功能 1]
- **F2**: [核心功能 2]

### P1（应该有）

- **F3**: [重要功能 1]
- **F4**: [重要功能 2]

### P2（可以有）

- **F5**: [锦上添花的功能]

## 业务规则 / 边界条件

- [规则 1：描述]
- [规则 2：描述]
- [边界情况：如何处理]

## 非功能需求

- **性能**：[响应时间、并发量等要求]
- **安全/隐私**：[数据安全、权限等要求]
- **成本**：[资源、预算等约束]

## 风险与取舍

- [风险 1：描述 + 应对方案]
- [取舍 1：选择 A 而非 B 的理由]

## 决策与假设列表

- **D1**: [决策内容] — 理由：[为什么这么决定]
- **A1**: [假设内容] — 依据：[基于什么做的假设]
```

## 写作指南

### 功能 ID

- 每个功能使用稳定 ID：`F1`、`F2`、`F3`...
- ID 用于验收标准关联，不要随意改动

### 优先级定义

| 级别 | 含义 | 标准 |
|-----|------|------|
| P0 | 必须有 | 没有这个功能产品无法使用 |
| P1 | 应该有 | 核心体验的重要组成部分 |
| P2 | 可以有 | 锦上添花，可后续迭代 |

### 决策与假设

- **决策 (D)**：你主动做的选择，需说明理由
- **假设 (A)**：基于推断的内容，需说明依据

### 下游可执行

PRD 面向设计师和开发者，必须达到：

- 设计师能直接画图：页面结构、跳转关系、交互细节都有
- 开发者能直接编码：功能清单、业务规则、验收标准都清楚
- 不需要再来回确认：一次输出，下游直接执行
