# 验收标准模板与写作指南

## 模板

使用 Given / When / Then 格式，按功能点组织。

```markdown
# 验收标准（Acceptance）

## F1: [功能名称]

### AC1: 成功路径

- **Given**: [前置条件]
- **When**: [用户操作]
- **Then**: [预期结果]

### AC2: 空状态

- **Given**: [前置条件，如数据为空]
- **When**: [用户操作]
- **Then**: [预期结果]

### AC3: 失败路径

- **Given**: [前置条件]
- **When**: [用户操作导致失败]
- **Then**: [预期结果，如错误提示]

### AC4: 边界情况

- **Given**: [边界条件]
- **When**: [用户操作]
- **Then**: [预期结果]

## F2: [功能名称]

### AC5: ...

...
```

## 写作指南

### ID 规则

- 验收标准使用全局递增 ID：`AC1`、`AC2`、`AC3`...
- 按功能点（F1、F2...）分组组织
- ID 一旦分配不要改动，方便追溯

### 必须覆盖的场景

每个 P0 功能至少覆盖：

| 场景 | 说明 | 必须 |
|-----|------|-----|
| 成功路径 | 正常流程走通 | ✅ |
| 空状态 | 无数据时的表现 | ✅ |
| 失败路径 | 异常情况处理 | ✅ |
| 边界情况 | 极端输入/状态 | 按需 |

### Given / When / Then 写法

- **Given**：前置条件，描述测试开始时的状态
- **When**：用户操作，描述触发行为
- **Then**：预期结果，描述系统应有的响应

### 示例

```markdown
## F1: 添加收支记录

### AC1: 成功添加记录

- **Given**: 用户已登录，在首页
- **When**: 点击"添加"按钮，填写金额 100、分类"餐饮"，点击保存
- **Then**:
  - 显示"保存成功"提示
  - 返回首页
  - 列表顶部显示新记录

### AC2: 金额为空时添加失败

- **Given**: 用户在添加页面
- **When**: 金额留空，点击保存
- **Then**:
  - 显示错误提示"请输入金额"
  - 不跳转，停留在当前页面
```

### 与 PRD 的关系

- 每个 AC 应关联到 PRD 中的功能点（F1、F2...）
- P0 功能必须有验收标准
- P1/P2 功能建议有验收标准
