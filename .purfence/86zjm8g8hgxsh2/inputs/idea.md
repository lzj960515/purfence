# Idea

## 需求描述（原文）

**标题**：支持远程 Git 仓库集成与多人协作工作流

## 背景

当前 Purfence 的工作流是自包含的：
1. 自己创建需求（issue）
2. 开出 worker tree
3. 天机团队工作
4. 自动完成并合并

但对于已有项目（如 GitLab 集成），需要支持：
- 同步远程分支
- 基于远程 issue 开 worktree
- 多人协作场景下不自动合并/推送

## 需求改进

### 1. 支持同步远程分支并开 worktree

**场景**：项目已有 GitLab/GitHub issue，需要基于远程分支工作

**功能**：
- 支持读取远程仓库的 issue（GitLab/GitHub API）
- 同步远程分支到本地
- 基于远程分支开出 worktree
- 或者：支持导入已有的远程 issue

**示例流程**：
```
GitLab issue #123 → 同步到 Purfence → 开 worktree → 天机团队工作
```

### 2. 多人协作模式

**场景**：多人协作项目，不想自动合并和推送

**功能**：
- 增加配置选项：`autoMerge: false`
- 增加配置选项：`autoPush: false`
- 完成需求后：
  - 不自动合并到 main
  - 不推送到远程
  - 只保留在本地 worktree
  - 用户手动决定何时合并/推送

**配置示例**：
```json
{
  "workflow": {
    "autoMerge": false,
    "autoPush": false,
    "requireManualApproval": true
  }
}
```

### 3. 工作流模式切换

支持两种模式：

| 模式 | 自动创建 issue | 自动合并 | 自动推送 | 适用场景 |
|------|---------------|---------|---------|---------|
| **单机模式**（当前） | ✅ | ✅ | ✅ | 个人项目 |
| **协作模式**（新增） | ❌（使用远程 issue） | ❌ | ❌ | 团队项目 |

## 涉及改动

### 1. 配置系统
- 添加工作流配置选项
- 支持项目级配置

### 2. Git 集成
- 支持同步远程分支
- 支持读取远程 issue（GitLab/GitHub API）
- 支持基于远程 issue 开 worktree

### 3. 完成流程
- 根据配置决定是否合并
- 根据配置决定是否推送
- 增加手动确认步骤

### 4. 天府评估
- 支持评估远程 issue
- 支持配置化工作流程

## 验收标准

- [ ] 支持同步远程 Git 仓库分支
- [ ] 支持基于远程 issue 开 worktree
- [ ] 支持配置 `autoMerge: false`，完成时不自动合并
- [ ] 支持配置 `autoPush: false`，完成时不自动推送
- [ ] 支持单机/协作两种工作流模式切换
- [ ] 多人协作场景下工作正常

## 优先级

**P0（高优先级）** - 架构改进，支持更多使用场景
