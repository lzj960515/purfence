# Idea

## 需求描述（原文）

**标题**：修改紫微提示词 - 修复重复创建需求问题

## 背景

当前紫微在创建项目时存在重复创建需求的问题。

## 问题描述

**当前行为**：
1. 紫微调用 `createProject` 工具创建项目
2. `createProject` 工具**内部逻辑已经自动创建了第一个需求**（默认需求）
3. 紫微**又额外调用了 `createIssue`** 工具
4. 结果：一个项目 + **两个需求**（重复了）

**问题代码示例**：
```typescript
// 紫微当前行为（错误）
const project = await createProject({ name, slug, description });
const issue = await createIssue({ projectId: project.id, ... }); // ❌ 重复创建
```

## 修复方案

重写紫微的系统提示词，明确新的交互流程：

### 核心原则

1. **不要添加额外信息** - 只整理用户说的内容，不主动添加东西
2. **整理原则**：
   - 去除重复啰嗦的话
   - 修正错别字
   - 保留所有细节，不要遗漏
   - 检查内容是否有冲突/矛盾（用户说一半反悔的情况）
3. **确认机制**：
   - 创建项目前 → 必须让用户确认项目描述
   - 创建需求前 → 必须让用户确认需求描述

### 交互流程示例

```
用户：我想做一个博客系统，可以写文章、评论，啊不对，评论功能先不要...

紫微：
1. 整理内容："创建一个博客系统，支持发布文章"
2. 检查冲突：已去除评论功能（您后来表示暂时不需要）
3. 向用户确认："我将为您创建项目：博客系统，支持发布文章。确认吗？"
4. 用户确认后 → 调用 createProject
5. 项目创建完成
6. 询问下一步
```

### 详细步骤

**创建项目流程**：
1. 用户表达想法后，先整理内容
   - 去除重复啰嗦的话
   - 修正错别字
   - 检查是否有冲突/反悔（如用户先说要某功能，后又说不要）
2. 向用户确认项目描述
   - 展示整理后的内容
   - 询问用户是否确认
3. 用户确认后，调用 createProject
   - description 使用整理后的内容
   - 系统会自动创建第一个需求（无需再调 createIssue）
4. 项目创建完成后，询问用户下一步

**创建需求流程**：
1. 用户提出新需求后，先整理内容
2. 向用户确认需求描述
3. 用户确认后，调用 createIssue
4. 需求创建完成后，询问用户下一步

### 涉及文件

- `backend/src/purfence/prompts/ziwei.prompt.ts` 或紫微系统提示词配置


## 验收标准

- ✅ 修改紫微提示词，明确"不要添加额外信息"原则
- ✅ 修改紫微提示词，明确"整理内容"步骤（去重、纠错、检查冲突）
- ✅ 修改紫微提示词，增加"确认机制"（创建前必须让用户确认）
- ✅ 修改紫微提示词，说明 createProject 已自动创建需求（无需再调 createIssue）
- ✅ 测试验证：创建项目前会询问用户确认
- ✅ 测试验证：创建项目后只有一个需求（不是两个）
