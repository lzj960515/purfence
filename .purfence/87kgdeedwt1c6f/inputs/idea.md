# Idea

## 需求描述（原文）

**标题**：将后端 Agent 的工具能力暴露给紫微

## 背景

**现状**：
1. **后端 Agent**（通过 Task 工具工作的团队）可以使用各种工具：
   - 读取/写入文件
   - 搜索代码
   - 执行命令
   - 等等

2. **紫微**（Purfence 的对话前台）**不能直接使用这些工具**：
   - 用户问我"帮我读取某个文件"，我无法直接读取
   - 用户问我"帮我搜索代码"，我无法直接搜索
   - 我只能通过创建 Issue，让后端团队去做

**问题**：
- 很多简单的文件操作、信息查询，紫微无法直接处理
- 需要创建 Issue，走完整的工作流，效率低

## 目标

**让紫微也能直接使用后端 Agent 的那些工具**，而不需要通过创建 Issue。

**举例**：
- 用户："帮我读取 ~/test.txt 文件"
- 紫微：直接调用 `read_file` 工具读取，立即回复内容
- 而不是：创建 Issue → 天机团队 → 后端团队 → 读取文件 → 返回结果

## 实现方式

### 1. 调研后端 Agent 有哪些工具
- 让后端团队列出他们能使用的所有工具
- 记录每个工具的：
  - 工具名称
  - 功能描述
  - 参数定义
  - 返回值格式

### 2. 为紫微创建相同的工具
- 在紫微的工具集中添加这些工具
- 参数、返回值、描述与后端工具保持一致
- 调用相同的底层实现

### 3. 验证紫微可以使用
- 测试紫微能否直接调用这些工具
- 验证功能与后端 Agent 一致

## 验收标准

- [ ] 调研并列出后端 Agent 的所有工具
- [ ] 紫微可以使用相同的工具
- [ ] 参数、返回值格式一致
- [ ] 紫微可以直接处理文件读取、代码搜索等简单任务，无需创建 Issue

## 优先级

**P1（中高优先级）**
