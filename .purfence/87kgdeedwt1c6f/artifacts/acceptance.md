# 验收标准（Acceptance）

## F1：紫微理解文件操作请求

### AC1：识别读取文件请求

- **Given**: 用户在紫微对话界面中
- **When**: 用户发送"帮我看看 README.md 里写了什么"
- **Then**:
  - 紫微判断这是"结果类"请求
  - 紫微决定使用 Task 工具处理
  - 紫微开始构造 Task 工具调用

### AC2：识别搜索代码请求

- **Given**: 用户在紫微对话界面中
- **When**: 用户发送"帮我搜索代码中所有名为 foo 的函数"
- **Then**:
  - 紫微判断这是"结果类"请求
  - 紫微决定使用 Task 工具处理
  - 紫微开始构造 Task 工具调用

### AC3：识别执行命令请求

- **Given**: 用户在紫微对话界面中
- **When**: 用户发送"帮我运行 npm test"
- **Then**:
  - 紫微判断这是"结果类"请求
  - 紫微决定使用 Task 工具处理
  - 紫微开始构造 Task 工具调用

### AC4：区分推进类与结果类请求

- **Given**: 用户在紫微对话界面中
- **When**: 用户发送"在项目中添加一个 README 文件"
- **Then**:
  - 紫微判断这是"推进类"请求（需要创建 Issue）
  - 紫微引导用户创建需求，而非使用 Task 工具直接执行

---

## F2：紫微正确调用 Task 工具

### AC5：正确设置 cwd 参数（用户指定路径）

- **Given**: 用户请求读取文件，并提供了绝对路径 "/Users/test/project/README.md"
- **When**: 紫微调用 Task 工具
- **Then**:
  - cwd 设置为 "/Users/test/project"
  - prompt 包含 "读取 README.md 文件"
  - subagent_type 设置为 "default"

### AC6：正确设置 cwd 参数（项目上下文）

- **Given**: 用户之前提到"博客项目"，现在请求"看看 README.md"
- **When**: 紫微调用 Task 工具
- **Then**:
  - 紫微先调用 searchProjects 定位项目
  - cwd 设置为项目的 localRootPath/repo
  - prompt 包含 "读取 README.md 文件"
  - subagent_type 设置为 "default"

### AC7：正确构造文件读取 prompt

- **Given**: 用户请求"读取 src/app.ts 文件"
- **When**: 紫微调用 Task 工具
- **Then**:
  - prompt 明确指定 "使用 Read 工具读取 src/app.ts 文件"
  - prompt 包含文件路径或相对路径指示

### AC8：正确构造代码搜索 prompt

- **Given**: 用户请求"搜索所有包含 'TODO' 的注释"
- **When**: 紫微调用 Task 工具
- **Then**:
  - prompt 明确指定 "使用 Grep 工具搜索包含 'TODO' 的内容"
  - prompt 包含搜索模式或关键词

### AC9：正确构造命令执行 prompt

- **Given**: 用户请求"运行 git status"
- **When**: 紫微调用 Task 工具
- **Then**:
  - prompt 明确指定 "使用 Bash 工具执行 git status 命令"
  - prompt 包含要执行的命令

## F3：紫微展示文件操作结果

### AC10：展示文件读取结果

- **Given**: Task 工具成功读取了文件内容
- **When**: 紫微收到 Task 返回结果
- **Then**:
  - 紫微将文件内容清晰展示给用户
  - 如果是代码文件，紫微使用 renderArtifacts 触发代码高亮展示
  - 紫微提供简短说明，如"已为您展示 README.md 的内容"

### AC11：展示代码搜索结果

- **Given**: Task 工具成功搜索到代码匹配项
- **When**: 紫微收到 Task 返回结果
- **Then**:
  - 紫微以结构化方式展示搜索结果（文件路径、行号、匹配内容）
  - 紫微总结搜索结果数量和关键发现
  - 紫微询问用户是否需要进一步操作

### AC12：展示命令执行结果

- **Given**: Task 工具成功执行了命令
- **When**: 紫微收到 Task 返回结果
- **Then**:
  - 紫微将命令输出展示给用户
  - 如果命令有退出码，紫微说明执行状态
  - 紫微提供简短总结或建议下一步操作

### AC13：处理文件不存在的错误

- **Given**: 用户请求读取一个不存在的文件
- **When**: Task 工具返回文件不存在错误
- **Then**:
  - 紫微告知用户文件不存在
  - 紫微建议用户检查文件路径或使用 Glob/Grep 搜索相关文件
  - 紫微不展示技术性错误堆栈

### AC14：处理大文件内容

- **Given**: Task 工具读取了一个大文件（>500 行）
- **When**: 紫微收到 Task 返回结果
- **Then**:
  - 紫微选择展示文件的关键部分（如开头、结尾、或用户关心的部分）
  - 紫微说明文件较大，询问用户是否需要查看特定部分
  - 紫微可提供摘要或结构化概述

## F4：支持会话续写

### AC15：同一目标复用会话

- **Given**: 用户刚才让紫微读取了 README.md
- **When**: 用户继续请求"再看看 package.json"
- **Then**:
  - 紫微判断这是同一目标的延续
  - 紫微使用上一次 Task 调用的 session_id，传给 resume 参数
  - 新的文件读取在同一个会话中执行

### AC16：新目标创建新会话

- **Given**: 用户刚才让紫微读取了 README.md
- **When**: 用户切换到完全不同的任务，如"搜索所有测试文件"
- **Then**:
  - 紫微判断这是新目标或不同类型任务
  - 紫微不传 resume 参数，创建新的 Task 会话
  - 新任务不会污染之前的上下文

---

## F5：智能工作目录推断

### AC17：通过项目名称定位目录

- **Given**: 用户提到"在博客项目中看看 README.md"
- **When**: 紫微调用 Task 工具
- **Then**:
  - 紫微先调用 searchProjects(query="博客") 定位项目
  - 如果找到唯一匹配，紫微使用项目的 localRootPath/repo 作为 cwd
  - 如果找到多个匹配，紫微请用户确认项目

### AC18：无项目上下文时询问

- **Given**: 用户请求"看看 README.md"，但没有提供任何项目上下文
- **When**: 紫微无法确定工作目录
- **Then**:
  - 紫微询问用户："请问是在哪个项目目录下？"
  - 或紫微列出最近的项目供用户选择
  - 等待用户明确后再调用 Task 工具

---

## F6：结果优化展示

### AC19：代码文件使用 renderArtifacts

- **Given**: Task 工具成功读取了代码文件（.ts/.js/.py 等）
- **When**: 紫微收到 Task 返回结果
- **Then**:
  - 紫微调用 renderArtifacts 工具
  - 传递文件路径和类型（如 `{ path: '/path/to/file.ts', type: 'code' }`）
  - 前端以代码高亮方式展示文件内容

### AC20：搜索结果结构化展示

- **Given**: Task 工具搜索到多个代码匹配项
- **When**: 紫微收到 Task 返回结果
- **Then**:
  - 紫微以列表或表格形式展示搜索结果
  - 每个结果包含文件路径、行号、匹配内容
  - 紫微提供总数统计（如"共找到 5 处匹配"）

## 测试数据准备

### 测试项目

准备一个测试项目，包含以下内容：

```
test-project/
├── README.md
├── package.json
├── src/
│   ├── app.ts
│   └── utils.ts
└── tests/
    └── app.test.ts
```

### 测试文件内容

- **README.md**: 包含项目描述、安装说明、使用指南
- **package.json**: 包含项目依赖和脚本
- **src/app.ts**: 包含一些函数和 TODO 注释
- **src/utils.ts**: 包含工具函数

### 测试命令

- `npm test`: 运行测试
- `git log`: 查看提交历史
- `git status`: 查看工作区状态
