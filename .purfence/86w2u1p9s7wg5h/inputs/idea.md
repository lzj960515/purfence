# Idea

## 需求描述（原文）

**标题**：修正紫微提示词 - 明确只整理用户内容，不添加额外信息

## 背景

之前的需求（86w0s7z9je9sbv）已部分完成，但关于项目描述的要求需要修正。

## 需要修正的内容

### 1. 已正确（保留）
```
✅ 不再自动调用 createIssue 创建需求
✅ 项目创建后询问用户下一步
```

### 2. 需要修改（当前错误）

**当前提示词要求**（错误）：
```
要求撰写详细项目描述（背景、目标、功能、技术栈等）
```

**应改为**（正确）：
```
整理用户提供的内容作为项目描述，遵循以下原则：
1. 去重：去除重复啰嗦的表述
2. 纠错：修正明显的错别字
3. 保留细节：不要遗漏用户提到的任何内容
4. 检查冲突：处理用户说一半反悔或矛盾的情况（如"要评论功能...啊不对先不要"）
5. 不添加：不要主动添加技术栈、目标用户、市场分析等额外信息

重要：只整理，不添加。描述内容应完全来自用户输入。
```

### 3. 新增要求

**必须增加确认步骤**：
```
创建项目前，必须向用户展示整理后的内容并确认：

"我为您整理的项目信息如下：
【名称】xxx
【描述】xxx

确认创建这个项目吗？"

等待用户明确回复"确认"或"是"后再调用 createProject。
```

## 涉及文件

- `backend/src/purfence/agents/ziwei.md` 或紫微系统提示词配置

## 验收标准

- ✅ 提示词中明确"只整理用户内容，不添加额外信息"
- ✅ 列出整理的具体原则（去重、纠错、保留细节、检查冲突、不添加）
- ✅ 明确说明"不要主动添加技术栈、目标用户等信息"
- ✅ 增加"创建前必须让用户确认"的要求
- ✅ 保留"不再自动调用 createIssue"的要求
- ✅ 测试验证：紫微创建项目前会先展示内容并询问确认
- ✅ 测试验证：项目描述不包含未提及的技术栈等信息
